# Decisions

- Pin the TypeScript 5 release line for compatibility with tsup declaration builds and ts-morph. Node 22.18 is the supported runtime floor.
- Keep public API notes in package READMEs to honor the repository owner's preference for code without comments.
- Use source file modification times for the analyzer's generation timestamp so repeated analysis of unchanged files yields identical bytes.
- Keep canonical functions under modules and show a step's function and call neighbors through a reference. This preserves one function ID and one containment parent even when several steps call it.
- Keep the analyzer free of runtime hooks. The loader consumes the instrument manifest, the server owns trace-to-node mapping, and the viewer reads graph and trace state through HTTP and SSE.
- Use bounded synchronous delay for the opt-in demo latency so the create handler keeps the specified one-call-per-statement shape. No delay runs by default.
- Share Zod with the demo for input, SQLite rows and traffic response validation. Use the matching SQLite type declarations for strict TypeScript.
- Use the SDK's current `@opentelemetry/sdk-trace` batch processor, Node HTTP instrumentation and JSON exporter. Their companion packages are required to configure the specified protocol and sampling delay.
- The server recognizes legacy HTTP semantic attributes as well as the current names. HTTP 4xx responses appear as failed requests in Flowlens, including when the HTTP instrumentation leaves span status unset.
- Keep a per-trace mapper across split OTLP batches so an early span can be assigned to a step when its request span arrives, without counting that function twice.
- Enable always-on sampling for the local viewer regardless of ambient OpenTelemetry sampling settings. Trigger the SDK's built-in HTTP hooks before the ESM app starts, so named imports and wrapped functions share a request context.
- Show canonical functions in a module with no routes, so database and audit modules remain navigable at system level.
- Playwright's configuration uses its required default export. Library entry points remain named exports.
- Load ELK's worker as a local build asset to keep layered layout off the browser's UI thread.
- The CLI prints an absolute tracer file URL and the exact collector URL. The target project can start with tracing without a separate dependency install.
- Pack with pnpm before the npm dry-run so the published manifests contain real version references in place of `workspace:*`.
- Bundle selected Devicons React components for Pinecone, database clients and frameworks. Infer technologies from imports, local client initializers and direct project calls. The viewer uses a generic database icon for database paths without a recognized brand.
- Publish the CLI as `@nazs/flowlens` and support packages as `@nazs/flowlens-*` so other projects can share the `@nazs` scope. Stage releases from GitHub Actions and use npm's 2FA approval to make them public.
- Use shadcn/ui Card composition with Tailwind utilities scoped to the viewer build. Summaries come from graph relationships and declared function signatures.
- Save the app entry during interactive CLI setup and use it to launch tracing from `dev`. Send the app's output and CLI diagnostics to stderr so stdout is a single viewer URL.
